# 哈达铺红军街 3D 互动地图设计说明

## 目标

建设一个可通过 GitHub Pages 直接访问的单页演示网页。首屏完整呈现用户提供的“哈达铺红军街空间故事线”地图，仅对拥有 GLB 模型的五处旧址增加可点击微光热点。点击热点后，弹出带红色长城水彩背景的沉浸式详情层，左侧展示可旋转、缩放和重置的 3D 模型，右侧展示旧址介绍与历史故事。

## 已确认范围

- 可交互旧址：红军门、邮政代办所、同善社、关帝庙、张家大院。
- 地图上其他文字保留为地图内容，但不增加交互，避免出现没有模型和文案的空详情。
- 五张建筑参考照片只用于理解素材，不出现在网页中。
- 使用用户提供的地图 JPG、长城水彩 PNG、五个 GLB 和五份 DOCX 文案。
- 页面不依赖后端、账号、数据库或第三方 API。
- 目标公开地址：`https://leizhidong-creator.github.io/Red-Army-Street/`。

## 视觉方向

整体采用“革命历史叙事 + 当代数字展陈”风格。地图保持原始手绘质感，不覆盖大面积面板；互动点使用克制的朱红、鎏金微光和慢速呼吸动画。详情层以长城水彩为背景，配合墨黑、象牙白和少量青绿色形成层次，避免单一红色造成疲劳。

详情层占桌面视口约 92% × 84%，金色细边框和高透明材质让背景仍可辨认。左侧模型区域不使用厚重卡片，建筑始终是主角；右侧通过竖向分隔线、标题、引文式导语和正文建立清晰阅读顺序。移动端改为模型在上、文字在下的纵向布局。

## 交互流程

1. 页面打开后直接进入地图，不增加营销式封面。
2. 五个热点在地图对应位置缓慢呼吸，悬停时亮度和标记范围增加。
3. 点击热点后，详情层从该位置平滑展开，并锁定底层地图滚动。
4. 模型加载完成后按本地包围盒居中、落地并自动构图；未操作时缓慢巡展。
5. 用户拖拽后自动巡展停止。滚轮或双指缩放，工具按钮提供重置视角和全屏模型。
6. 点击关闭按钮、遮罩或按 `Escape` 返回地图，焦点回到原热点。

热点坐标使用相对于地图原图的百分比，跟随响应式缩放：

| 旧址 | 地图锚点（x, y） | 说明 |
| --- | --- | --- |
| 红军门 | 22%, 82% | 对应地图“南口入口” |
| 同善社 | 16%, 70% | 对应“同善社旧址” |
| 邮政代办所 | 27%, 31% | 对应“邮政代办所” |

## 3D 展示

- 使用 Three.js / React Three Fiber 加载 GLB，不改写或降质原模型。
- 每次加载从脱离展示父级的模型测量包围盒，X/Z 居中并将最低 Y 放在地面。
- 相机距离由包围球、垂直/水平视场角和边距共同计算，默认视图必须显示完整轮廓。
- 轨道控制限制极端仰俯角和过度缩放，避免穿模或看见不可信底部。
- 使用本地灯光、接触阴影和透明地面，不请求外部 HDR 或纹理。
- 加载失败时保留详情文案并显示明确的模型加载错误，不让整个页面崩溃。

## 内容与数据边界

每个旧址由一条结构化数据记录驱动，包含 `id`、名称、地图坐标、GLB 路径、导语、正文和时间/人物标签。文案以用户 DOCX 为事实来源，对明显 OCR 错字做最小校正，不添加未经提供的史实。

## 工程与部署

- Vite + React + Three.js + React Three Fiber + Drei。
- Vitest 覆盖地标数据、相机构图算法和主要打开/关闭交互。
- ESLint、生产构建和浏览器控制台检查必须通过。
- Vite `base` 固定为 `/Red-Army-Street/`，所有地图和 GLB 路径通过 `import.meta.env.BASE_URL` 解析。
- GitHub Actions 构建 `dist` 并部署 GitHub Pages；不提交源 DOCX、参考照片、临时文件或密钥。
- 桌面验收尺寸为 1366×768、1440×900；另验收 390×844 移动端。

## 完成标准

- 公开 URL 可访问，地图与五个 GLB 均无 404。
- 五个热点均能打开正确模型与正确文案。
- 默认模型完整、居中、无明显悬空，重置后回到同一视角。
- 页面无横向错位、文本遮挡、按钮溢出或控制台错误。
- 建模参考照片未被打包进网页。
